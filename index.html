CUDA Optimization of Multi-Head Attention

Dominik Djajadi · Individual project

Status: Baseline complete · Optimization in progress

Overview

This project investigates the performance of a complete multi-head attention (MHA) forward pass implemented in CUDA C++. The focus is on communication, memory traffic, and the distribution of work across and within attention heads.

Starting with a straightforward FP32 implementation, the project uses profiling to guide optimizations and measures improvements in end-to-end layer performance.

Milestone Progress — November 23

The complete naive MHA forward pass is implemented, including Q/K/V projections, scaled dot-product attention, head packing and concatenation, and the final output projection. The implementation uses custom CUDA kernels and has passed correctness tests against an independent CPU reference across eight configurations.

Initial end-to-end benchmarks and Nsight Systems profiling have also been completed on an NVIDIA GeForce RTX 2080. The main performance concern identified so far is the one-thread-per-row softmax implementation.

At N=512, D=256, H=8, the baseline median forward-pass time was 6.4151 ms. Softmax accounted for 65.4% of measured GPU kernel execution time.

Revised Optimization Plan

  1. Parallel softmax: Replace one-thread-per-row processing with cooperative warp- or block-level reductions.
  2. Head-level parallelism: Investigate concurrent processing across attention heads.
  3. Profiling: Remeasure the implementation and identify new bottlenecks.
  4. Shared-memory matrix multiplication: Investigate tiling and data reuse in the GEMM kernels.
  5. Memory layout: Evaluate packing, unpacking, and intermediate data movement.

Selective kernel fusion and FlashAttention-style online softmax remain stretch goals.

Evaluation Goals

The primary objective is to achieve substantial performance improvements over the naive CUDA baseline and explain the parallel programming tradeoffs behind those changes. PyTorch will serve as an additional optimized reference, rather than a performance target that must be surpassed.

Final comparisons will emphasize end-to-end runtime, component-level profiling, sequence-length scaling, and the effects of work distribution and memory reuse.
